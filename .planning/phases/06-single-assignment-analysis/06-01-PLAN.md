```typescript
/** Confidence level for a regrade recommendation. Binary per user decision. */
export type AnalysisConfidence = "LIKELY" | "POSSIBLE";

/** A single regrade recommendation for one rubric item. */
export interface AnalysisRecommendation {
  /** Which question this finding belongs to (e.g., "Q1", "Question 3") */
  question: string;
  /** The specific rubric item name where points may have been incorrectly deducted */
  rubricItem: string;
  /** Description of the potential grading error */
  issue: string;
  /** Evidence from the submission (direct quote or description) */
  evidence: string;
  /** Binary confidence: LIKELY (strong evidence) or POSSIBLE (worth checking) */
  confidence: AnalysisConfidence;
  /** Points that could potentially be recovered */
  potentialRecovery: number;
}

/** Summary section at top of analysis output. */
export interface AnalysisSummary {
  /** Current total score on the assignment */
  currentScore: number;
  /** Maximum possible score */
  maxScore: number;
  /** Number of findings across all questions */
  totalFindings: number;
  /** Estimated total recoverable points */
  estimatedRecovery: number;
}

/** Complete analysis result for one assignment. */
export interface AnalysisResult {
  /** Top-level summary stats */
  summary: AnalysisSummary;
  /** Per-question recommendations, organized by question */
  recommendations: AnalysisRecommendation[];
  /** Questions that were analyzed but had no findings */
  noFindings: string[];
  /** Questions skipped due to illegible content */
  illegibleQuestions: string[];
}
```

Then create `src/analysis/prompt-builder.ts` with Zod schemas that mirror these types for runtime validation of Claude's structured output:

```typescript
import { z } from "zod";

export const AnalysisRecommendationSchema = z.object({
  question: z.string(),
  rubricItem: z.string(),
  issue: z.string(),
  evidence: z.string(),
  confidence: z.enum(["LIKELY", "POSSIBLE"]),
  potentialRecovery: z.number(),
});

export const AnalysisResultSchema = z.object({
  summary: z.object({
    currentScore: z.number(),
    maxScore: z.number(),
    totalFindings: z.number(),
    estimatedRecovery: z.number(),
  }),
  recommendations: z.array(AnalysisRecommendationSchema),
  noFindings: z.array(z.string()),
  illegibleQuestions: z.array(z.string()),
});

export type AnalysisResultValidated = z.infer<typeof AnalysisResultSchema>;
```

The prompt text must include these sections (follow the locked user decisions exactly):

**1. Context header:**
- Assignment name, course name, current score / max score
- Number of questions being analyzed (lost-point questions only — per decision: skip full-mark questions entirely)

**2. Per-question rubric data:**
- For each lost-point question: question name, score earned / max score, all rubric items that were applied (with their names, point values, descriptions, and grader comments if any)
- Group rubric items under their question name

**3. Analysis instructions:**
- Compare student work (shown in images above) against each rubric item that was applied
- Identify where rubric items may have been applied incorrectly
- Look for evidence that contradicts the deduction or suggests the grader missed content

**4. Constraints (locked decisions):**
- ONLY analyze rubric application correctness — never comment on rubric fairness or question design
- Use direct quotes when handwriting is clear, descriptions when unclear (Claude decides per finding)
- If handwriting is illegible, note it and skip — do NOT guess or speculate
- Frame ALL findings as "potential opportunities to investigate" — never definitive claims about errors
- Assign exactly one confidence level per finding: LIKELY (strong evidence of error) or POSSIBLE (worth checking)

**5. Output format:**
- Instruct Claude to respond with valid JSON matching the AnalysisResult shape
- Include the exact JSON schema structure in the prompt for Claude to follow
- Specify that `noFindings` should list question names analyzed but found no issues
- Specify that `illegibleQuestions` should list questions skipped due to unreadable content

**6. Tone guidance:**
- "You are helping a student identify potential grading errors to discuss respectfully with their instructor."
- "Protect the student-instructor relationship. The student will verify your findings before submitting any regrade request."
- "When in doubt, mark as POSSIBLE rather than LIKELY."
